## 一页总览

唯一主项目：**电商售后破损补发工作台**。给客服审核员使用：客户描述/订单号/图片 → 查询模拟订单和物流 → 找到适用政策版本 → 整理可见证据 → 生成带引用的结构化建议 → 人工审核 → 重查业务状态 → 幂等模拟补发 → 审计与评估。

| 阶段 | 你要获得的能力 | 看得见的产物 | 阶段门槛 |
| --- | --- | --- | --- |
| 第 1–4 周 | Python/API/数据契约、模型 SDK、工具循环、版本化政策检索 | 文本售后流程与第一份评估 | 输入工单，查到正确订单和适用政策，建议引用能逐条核对；缺依据时补材料或转人工 |
| 第 5–8 周 | SQL 持久化、状态、审批、幂等、图片证据、简单页面 | 图文审批原型 | 重启后找回待办；人工批准后才模拟补发；重复请求不重复创建；正常/缺材料/失败均可演示 |
| 第 9–12 周 | 评估、日志、权限故障、部署、项目表达 | 可复现仓库、报告、演示视频和面试材料 | 陌生人按 README 跑通样本并复现评估；结论有样本和代码依据 |
| 第 13–16 周 | 按岗位补一项能力、验证复用 | 改进对比、相邻流程、针对性讲述 | 原有回归不退步，新增能力有独立证据 |

8GB 显存、16GB 内存用于后端、SQLite、图片预处理和评估；模型主要走 API。第 1–4 周不要求训练模型或运行本地大模型。前端默认 Streamlit；先确保流程可用。SQL 先用 SQLite，按实际部署需求再考虑 PostgreSQL。

## 怎样才算项目驱动学习

每周按“提出业务问题 → 定向读课 → 亲手写一个最小实现 → 加失败输入 → 解释代码 → 留证据”推进。课程观看约 3–4 小时封顶，不把当周列出的所有节次全部看完作为要求：先看核心节，其他遇到问题再查。每周约 9 小时开发、3 小时课程、3 小时基础练习、2 小时评估和口述、1 小时复盘；基础练习直接围绕当周功能。

**你必须亲手练的核心代码：**Pydantic 输入输出模型；模型请求与消息；工具参数校验、白名单执行和限次循环；政策检索与版本过滤；SQL 查询和事务；状态转移；审批与幂等补发；图像证据整理；评估脚本和关键断言。

助手可以讲原理、给小例子、提示下一步、审查差异和协助排错。第一次练核心功能时先给接口约定和验收输入，让你实现；卡住时逐步提示。辅助目录、样式、重复样本可借助生成，但你仍需复核。不能以助手完成整个项目、你仅启动成功作为掌握证据。

每项核心能力通过三个动作验收：①不看现成实现，重写关键函数或说明每一步；②现场改一条业务规则；③给一个反例，定位失败在哪一层。做不到时记录“已运行，待独立练习”，不记作掌握。每周保留一次 5 分钟讲述和一次小改动记录。

## 参考资料怎样用

主要实现参考：[CS329Z assignment1-harness](https://github.com/cs329z/assignment1-harness)用于工具循环、检索与确定性测试组件练习，邮件/企业资料主题只迁移模式；[官方售后状态机教程](https://docs.langchain.com/oss/python/langchain/multi-agent/handoffs-customer-support)用于理解单 Agent 随状态改变工具/指令；[LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)和[人工中断](https://docs.langchain.com/oss/python/langgraph/interrupts)用于有需要时做恢复与审批。图节点恢复可能重复执行，业务副作用仍须幂等处理。API 的精确写法在实际使用时对照锁定依赖版本与官方文档。

[langgraph-support-agent](https://github.com/nitanandsinghupw/langgraph-support-agent)仅是小型可运行对照，既有 24/24 和 11/11 是前会话工具验证，不能写成你已学习或作品已验证。HelpPilot 仅参考页面/样本。图像素材第 7 周按原路线少量选 CC0 合成图加自摄图，逐条记来源并人工核对。完整边界与核查结论保留在主路线。

后续每次学习先报“第几周第几天、可用时间、上次实际结果”，据此发当日题目和验收输入；核心功能由你先动手，再一起审查。所有实际成绩只写入[学习进度](学习进度.md)。
