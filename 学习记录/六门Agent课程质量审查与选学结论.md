# 六门 Agent 课程质量审查与选学结论

审查日期：2026-11-23。对象是本地六门课，不包括 CMU 11-768 和 Stanford CS329Z。目标是在每周约 15–20 小时、12–16 周内，做出可用于面试的**电商售后破损补发工作台**：图像证据、版本化政策检索、只读工具、人工审批、幂等模拟补发、评估和可复现部署。现有[学习进度](学习进度.md)没有可信的已学章节记录，以下均为选学建议，不代表已经学会。

## 总体结论

| 课程 | 这 12 周的位置 | 判断 |
| --- | --- | --- |
| 尚硅谷 LangChain 2026 | **定向主学**，约 12–18 小时 | 六门中与模型调用、工具、结构化输出、审批机制和 RAG 的项目交集最大；但不能把 120 讲当作工程闭环。 |
| MCP+A2A 类 Manus 全栈 | **定向主学部分章节**，约 10–16 小时 | 工具循环、多模态、事件和持久化的代码量较扎实；完整 Manus 平台、A2A、浏览器和前端会挤掉售后业务、评估和部署时间。 |
| 小哲知识点动画 | **随查随看**，约 3–5 小时 | 适合快速补术语与面试表达；缺少可复现的项目代码和实验，不能作为实现依据。 |
| mksz938 编程智能体 | **针对性查阅**，约 4–7 小时 | 有工具、MCP 和 LangGraph 的第二种实现；后半段多为编程助手的终端、浏览器、百炼知识库与多 Agent，迁移成本高。 |
| 尚硅谷 Hermes | **产品观察**，约 1–2 小时 | 主要是现成 Agent 的安装、配置、记忆、技能与协作演示；不是售后 Agent 的开发教程。 |
| SpringAI 多 Agent | **Python 主线暂舍弃；Java 岗再选学**，当前 0–2 小时 | 有可读 Java 源码和图工作流示例，但版本、框架和旅行规划架构都增加切换成本；源码抽查还发现一个 Skills 示例挂载缺漏。 |

这不是课程好坏的总排名，也没有证据证明任何一门“骗钱”。它们的主要问题是**与当前面试作品的投入产出比**：六门共 770 节，重复讲 Agent、工具和 MCP；而售后权限、政策版本、审批后副作用、图像标注、回归评估与干净环境部署，仍需自己设计和验证。若已有课程，无需为“买了就看完”追加时间；若考虑继续付费，先确认可用源码、练习与更新维护，再按目标章节判断。

## 证据范围与判断口径

- 读了仓库 README、路线、逐章导读、学习进度；核对六门的 77 份分组文字稿所列 770 个视频标题，并抽查前段、目标章节和后段。三门有逐视频 SRT：MCP 全栈 248、小哲 81 个文件对应 79 节、Hermes 51；其余三门主要依据带时间戳的分章转录。**未逐一观看原视频**，因此不把转录中的错词直接认定为老师口误或课件错误。
- 六份课件/代码 ZIP 逐一检查目录及加密标记。MCP 全栈、编程智能体、Hermes、LangChain 的 ZIP 中文件均带加密标记，未取得密码，也未读取里面的 PDF、PPT 或源码；不能据此断言其源码质量或缺少练习。SpringAI 的 `AiTripPlan-master.zip` 可读，抽查 README、POM、Graph 配置、Skills 示例；包中 419 个 Java 文件、20 个 POM，未发现 `src/test` 源码。这说明**提供的包内**未见自动测试，不等于课程没有演示验证。
- “有演示”与“经得起面试复测”分开判断。讲了工具调用、RAG 或审批，不等于已覆盖跨商户授权、政策生效期、人工身份、补发唯一键、超时后结果查询、留出集和部署恢复。课程中看不到这些内容时，本文只说**抽查未见**，不宣称全课绝无。
- 核了能找到的一手课程介绍：尚硅谷[2026 版 LangChain 课程公告](https://www.atguigu.com/news/17206)明确称基于 LangChain 1.2.12、有三个综合项目；其“客服知识库”与本地 117–120 讲一致，但“企业级”是营销定位，不能直接推出售后审批/幂等/评估能力。尚硅谷[Hermes 课程导航](https://atguigu.com/video/llm/)列五个模块和博客自动发布案例，与本地 43–50 讲相符；“亲手打造 Agent”在这里主要是配置与组合 Hermes 能力。其余课程未检到足以独立核实更新承诺和练习质量的官方课程页，结论以本地目录、转录及可读源码为限。
- 时间是**建议投入上限**，包含看选定视频、对照官方文档和在自己项目重做一个小功能，不是课程视频总时长，也不是宣称已验证的学习效果。每周课程/文档合计约 3–4 小时，目标交付优先。

### 当前技术核对

1. LangChain 官方[结构化输出](https://docs.langchain.com/oss/python/langchain/structured-output)仍使用 `create_agent(response_format=...)`，并区分 ProviderStrategy 和 ToolStrategy；模型能力、`strict` 等有版本门槛。官方[人工审核中间件](https://docs.langchain.com/oss/python/langchain/human-in-the-loop)确实支持批准、编辑、拒绝和恢复，但依赖持久化，且审批工具调用不自动解决业务数据库的幂等与授权。官方[LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)区分 thread 检查点与跨 thread store；[interrupt 规则](https://docs.langchain.com/oss/python/langgraph/interrupts)特别提醒中断前的副作用要幂等。
2. MCP 官方 [2026-07-28 工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)仍支持工具发现/调用，也强调人可拒绝工具调用。与部分课程录制时不同，[2026-07-28 规范说明](https://blog.modelcontextprotocol.io/posts/2026-07-28/)已调整初始化、会话及授权等机制。故课程的 MCP **概念可以学，报文、传输、缓存和鉴权代码不能原样当最新规范**；尤其不可把 MCP 会话当售后用户/商户的授权边界。
3. SpringAI 课源码含 Spring AI Alibaba `1.1.0.0-RC2`、`1.1.2.0` 和扩展 `1.1.2.1` 的示例。官方[Spring AI Alibaba 发布记录](https://github.com/alibaba/spring-ai-alibaba/releases)可见 1.1.2.1 后续修复和 2.0 里程碑；[Spring AI MCP 文档](https://docs.spring.io/spring-ai/reference/api/mcp/mcp-overview.html)列出依赖/导入的破坏性调整。版本风险是“复制时需按所选稳定版本迁移”，不是“当时教错”。
4. 用 [Stanford CS329Z 项目标准](https://cs329z.stanford.edu/project.html)校准深度：早定评价口径、基线、失败分析、可复现运行。这是本作品的质量要求，并非六门之一，也不是要求完成大学课作业。

## 逐门结论

### 1. MCP+A2A 从 0 到 1 构建类 Manus 多 Agent 全栈应用（248 节，20 章）

**实际路线。**先讲 Agent/ReAct、模型 API、图像和工具调用，再搭 FastAPI、数据库、MCP、规划/执行 Agent、浏览器与沙箱、A2A、会话/事件、Next.js 和 Docker。不是“仅讲概念”：9-6 从工具结果模型和装饰器实现本地工具，16-2～16-7 做会话表、仓库、消息交互和记忆持久化；后段继续做到前端和部署。

**抽查依据。**[第 4 章转录](<../课程文字稿/MCP+A2A 从0到1构建类Manus多Agent全栈应用/第4章 技术栈与环境准备：DeepSeek与OpenAI SDK库实操.txt>)的 4-7 清楚讲出“模型提议工具、程序执行并回传”的两步过程，并留练习；4-5、4-8、4-9 分别碰图像、Pydantic、JSON 输出。[第 7 章](<../课程文字稿/MCP+A2A 从0到1构建类Manus多Agent全栈应用/第7章 MCP协议初识：统一LLM与外部数据源和工具之间的通信.txt>)7-5 演示不用 SDK 接高德 MCP；[第 9 章](<../课程文字稿/MCP+A2A 从0到1构建类Manus多Agent全栈应用/第9章 Agent模块开发：基于事件与后台运行的Agent模块开发.txt>)9-6、9-10 涉及工具封装和状态；[第 16 章](<../课程文字稿/MCP+A2A 从0到1构建类Manus多Agent全栈应用/第16章 上下文工程：完善各个Agent功能与上下文优化.txt>)16-6 的“消息工具”能通知/询问用户，但并非售后审批身份与补发事务；[第 19 章](<../课程文字稿/MCP+A2A 从0到1构建类Manus多Agent全栈应用/第19章 部署篇：Dockerfile与docker compose实现项目一键部署.txt>)19-2 主要是给 Cursor 提示词生成 Dockerfile/compose/README，19-3 转域名证书。对应的 [248 份 SRT](<../逐视频字幕/MCP+A2A 从0到1构建类Manus多Agent全栈应用/>)可进一步核视频语句；课件 ZIP 的 67 个文件条目带加密标记，源码未核。

**优点。**从 SDK 级工具到后台事件、DB、前端有连续的实现路线；对有开发经验的用户，4、9、16 章能提供具体代码拆解，而不只讲 Agent 名词。**不足与过时。**工程架构服务于通用 Manus，包含 Redis Streams、浏览器、沙箱、A2A、多前端模块；对单商户售后工单过重。图像章节是模型图像输入，并未在抽查中看到商品破损标注/误判分析。部署章有生成配置演示，抽查未见干净环境重建、数据迁移、故障恢复或留出集评估。MCP 实作需按当前规范复核。

**选法。**精学 4-5～4-9、9-5～9-10；做状态时看 16-2～16-7；第 9 周需要展示 MCP 才看 7-2～7-7、10-7～10-10；5-5～5-6、6 章按具体工程问题查。3 章概念快看。11–15、完整 17–18、19-3～19-4 暂跳；19-2 只作生成配置的例子，部署验收靠自己的重建。**投入/交付：**10–16 小时，交付一个自己写的图像输入/只读工具循环或会话持久化小模块。**信心：中高**（目录、目标与后段转录及 SRT 可核；源码/课件加密，未运行课程项目）。

### 2. 小哲大模型 Agent 应用开发知识点动画讲解（79 节）

**实际路线。**短节解释 Agent、LLM、Prompt、工具、状态、单/多 Agent、RAG 和面试题，主要是概念类动画与口述，不是完整应用代码课。

**抽查依据。**[逐视频字幕](<../逐视频字幕/【AI课程】小哲大模型Agent应用开发知识点动画讲解视频/>)27 谈 LLM 质量，40–41 谈提示注入，58 用状态机和合法状态转移解释恢复，73–79 谈召回、精排与 RAG 落地；79 明确提到评估、线上运维和数据治理比“接一个向量库”难。与 [分章转录](<../课程文字稿/【AI课程】小哲大模型Agent应用开发知识点动画讲解视频/>)核对。该课程目录未见对应可读源码包。

**优点。**术语解释短，58、79 的工程方向符合本项目风险，适合面试前快速整理表达。**不足。**不少内容停在“应该做状态机/分层防御/优化召回”的层面，未提供业务状态表、授权测试、数据集与可复现实验；某些比喻或绝对化句子只能作入门简化，技术定义仍需核官方资料。不要把讲到“评估”当成学会评估。

**选法。**只看 27–30、40–41、48–58、63–69、73–79 中当周真正卡住的短节；1–26 已会则跳，31–39 的训练/Prompt 概览按需。**投入/交付：**3–5 小时，产出一页自己的术语解释、失败分支和指标定义，不能替代功能代码。**信心：中高**（有逐视频字幕，可核概念覆盖；未逐帧审视频，未见可运行课件）。

### 3. 尚硅谷 Hermes 小白教程（51 节）

**实际路线。**介绍并配置现成 Hermes Agent：模型、桌面/终端、会话、Dashboard、MCP、持久记忆、Skills、hooks、Cron、消息网关、Profile、Kanban；43–50 用多个 Profile、微信/定时推送和任务看板做协作案例。它教“使用一个成品”，不是从零构建售后服务。

**抽查依据。**[11–20 讲转录](<../课程文字稿/尚硅谷Hermes小白教程：2026必学的AI Agent框架/第11-20讲.txt>)的 11–13 是会话/看板；[21–30 讲](<../课程文字稿/尚硅谷Hermes小白教程：2026必学的AI Agent框架/第21-30讲.txt>)24 [SRT](<../逐视频字幕/尚硅谷Hermes小白教程：2026必学的AI Agent框架/24_能力篇_持久化记忆介绍/转录字幕.srt>)主要演示设置中开启持久记忆/用户画像；31 [SRT](<../逐视频字幕/尚硅谷Hermes小白教程：2026必学的AI Agent框架/31_进化篇_钩子系统的安全保护功能/转录字幕.srt>)解释工具执行前的 block hook，但讲者明确说危险命令“不好演示”，不能把这一段算作安全测试；[41–50 讲](<../课程文字稿/尚硅谷Hermes小白教程：2026必学的AI Agent框架/第41-50讲.txt>)44 配模型并创建四个 Profile，49 通过微信消息交给 Kanban。课件 ZIP 文件带加密标记，未读。

**优点。**可观察产品的轨迹、用户可见的工具行为和多角色协作界面；对审核员页面草图有启发。**不足。**配置/演示占比高，版本和外部服务变化会使点按步骤很快失效；hook 黑名单演示不能替代服务端权限、身份校验和危险工具最小授权。其“越用越智能”记忆叙述也不能拿来管理售后政策版本。

**选法。**最多看 11–13、21–27、30–31 中几个页面和机制演示，画一张审核员交互草图；安装、微信网关、Cron、四 Profile/Kanban 实战整段跳过。**投入/交付：**1–2 小时，一张界面草图和轨迹展示清单。**信心：高（内容类型），中（现时可复现性）**；有 51 份 SRT，但未实际安装或读取课件。

### 4. mksz938 AI Agent+MCP 个人编程智能体（168 节，20 章）

**实际路线。**先用 LangChain 做模型和工具，接 MCP、对话记忆；随后把终端、百炼知识库、浏览器、沙盒、MySQL、LangGraph 和多 Agent 组合成个人编程助手，18–19 章让它开发书城前后端。不是企业售后工作流课。

**抽查依据。**[第 4 章](<../课程文字稿/mksz938-AI Agent+MCP从0到1打造个人专属编程智能体（20章完结）/第4章 AI智能体开发之LangChain大模型工具开发 (Agent工具能力).txt>)4-7～4-8 自定义工具；[第 6 章](<../课程文字稿/mksz938-AI Agent+MCP从0到1打造个人专属编程智能体（20章完结）/第6章 AI智能体开发之深入MCP协议(AI Agent 的外部工具能力).txt>)6-7 本地 MCP；[第 11 章](<../课程文字稿/mksz938-AI Agent+MCP从0到1打造个人专属编程智能体（20章完结）/第11章 AI编程智能体开发之知识库开发(AI Agent的知识学习能力).txt>)11-2～11-5 是百炼建库、SDK 查询和 MCP 封装；[第 12 章](<../课程文字稿/mksz938-AI Agent+MCP从0到1打造个人专属编程智能体（20章完结）/第12章 AI编程智能体开发之RAG自学习机制(AI Agent的自主学习能力).txt>)12-2～12-9 是文件上传/向量任务 API，12-10 实操中还出现文件不存在和模块导入问题，讲者现场修；[第 17 章](<../课程文字稿/mksz938-AI Agent+MCP从0到1打造个人专属编程智能体（20章完结）/第17章 AI编程智能体开发之实现代码辅助开发能力（AI Agent的辅助编程能力）.txt>)17-1～17-4 用关键词/百度搜索示范图，17-6 Supervisor 是数学和搜索工具的官方小例子；[第 19 章](<../课程文字稿/mksz938-AI Agent+MCP从0到1打造个人专属编程智能体（20章完结）/第19章 智能体实际项目中落地：小慕书城后端API与数据库自动化开发（后端项目实战）.txt>)19-6 让 Agent 生成 CRUD 并建议 curl 测试。源码 ZIP 文件带加密标记，未读，不能据转录判断最终代码是否修复。

**优点。**手把手整合多个工具和外部服务，现场出现报错也有排查过程，适合刚接触工具封装的人。**不足。**“RAG 自学习”大部分是托管百炼上传/向量化流程；把 Agent 总结自动写成知识，不适合有生效时间、商户范围和人工批准要求的售后政策。图与 Supervisor 示例展示 API，用例深度不足以替代故障恢复/人工审批。终端、浏览器、沙盒是编程代理的高权限能力，迁到售后项目会额外增加安全面。框架/API 随版本变化，须按官方文档重写。

**选法。**仅当 LangChain 主课解释不够时看 4-7～4-8、6-7；若采用 LangGraph 才看 16-4～16-6、17-1～17-4。11-2～11-5 只作为“托管 RAG 怎么接”的对照，不作为主学；12、10、13–15、17-5～17-7、18–19 暂跳。**投入/交付：**4–7 小时，交付一个自己写的只读工具/MCP 小演示或最小图状态示例。**信心：中**（标题和目标/后段转录可核；无逐视频 SRT，源码加密，未跑项目）。

### 5. 尚硅谷 LangChain 从入门到实战 2026 版（120 讲）

**实际路线。**从模型调用、消息和 Prompt 到工具、Pydantic/结构化输出、`create_agent`、中间件、检查点/记忆，最后是文档加载、切分、Embedding、Milvus 和客服知识库问答。它是组件与 API 教程；末尾“客服”是知识库问答，不是订单/图片/审批/补发闭环。

**抽查依据。**[31–40 讲](<../课程文字稿/尚硅谷LangChain从入门到实战（2026版）/第31-40讲.txt>)033 讲模型与程序执行工具的边界；[41–50 讲](<../课程文字稿/尚硅谷LangChain从入门到实战（2026版）/第41-50讲.txt>)041 解释结构化输出、后续用 Pydantic；[51–60 讲](<../课程文字稿/尚硅谷LangChain从入门到实战（2026版）/第51-60讲.txt>)含 ToolStrategy/ProviderStrategy；[61–70 讲](<../课程文字稿/尚硅谷LangChain从入门到实战（2026版）/第61-70讲.txt>)066 演示 HumanInTheLoopMiddleware 的批准/拒绝/编辑，069 控制模型调用次数；[81–90 讲](<../课程文字稿/尚硅谷LangChain从入门到实战（2026版）/第81-90讲.txt>)区分内存和外部检查点。[101–110](<../课程文字稿/尚硅谷LangChain从入门到实战（2026版）/第101-110讲.txt>)101 仍是长期记忆，102 才开始 RAG；[111–120](<../课程文字稿/尚硅谷LangChain从入门到实战（2026版）/第111-120讲.txt>)113–118 多为 Docker/Milvus 安装与写库，119–120 才是客服问答检索。代码和课件 ZIP 文件均带加密标记，未读，无法确认具体依赖锁定或练习质量。

**优点。**API 层的工具、输出策略、中间件、记忆和 RAG 讲得相对细；所抽 `create_agent`、结构化输出和人工审核核心用法与当前官方文档方向一致。**不足与过时。**讲解常在一个 API 上换 schema/参数反复演示，已经会 Python 的用户可快进。RAG 尾段把很多时间投入 Milvus 配置，政策量小的售后原型可先用版本化文本+关键词基线。客服案例未见订单权限、政策有效期、人工补发或图片；中间件审批也不能单独保证业务幂等。版本号、模型名和具体参数应对照当前文档，课件无法核实。

**选法。**精学 033–040、041–050 中自己不会的部分、054–059、061、066、069–070、102–112、119–120；087–095 只在采用 LangGraph 检查点时选。001–020、重复 schema 演示、长记忆和 113–118 Milvus 安装先跳。**投入/交付：**12–18 小时，交付一个能校验结构化建议、调用只读订单/政策工具、给出处并留失败日志的文本原型；审批与补发仍需自建业务状态。**信心：中高**（全 120 讲转录可核，关键 API 与官方对照；课件/源码加密，未实跑）。

### 6. 多 Agent+Skills+SpringAI 构建自主决策智能体（104 节，10 章）

**实际路线。**用 Spring AI Alibaba/AgentScope 做 MCP、A2A、ReAct、旅行规划团队、Graph、Jmanus、分布式和 Skills。源码包 README 明确列出 Spring AI 1.0/1.1/1.1.2 多个 Demo、旅行规划三种实现和 Jmanus，题目宣称与可读源码的范围基本一致。

**抽查依据。**[第 4 章](<../课程文字稿/多 Agent+Skills+SpringAI 构建自主决策智能体/第4章 SpringAi 1.1 实现 MCP+A2A.txt>)4-1～4-16 逐项讲 BOM、SSE/MCP、A2A；[第 7 章](<../课程文字稿/多 Agent+Skills+SpringAI 构建自主决策智能体/第7章 Graph 搭建旅游规划工作流，像拼积木一样轻松.txt>)7-1 定义路线、行程、费用、主管、汇总五个角色，7-5 讲 Edge；源码 `AiTripPlan-master.zip` 中 `WorkFlow-Graph-SpringAi 1.1/.../conf/GraphConfiguration.java` 确有路线/行程/预算/汇总节点及条件边。[第 10 章](<../课程文字稿/多 Agent+Skills+SpringAI 构建自主决策智能体/第10章 Skills 让 Agent 按照专业流程工作.txt>)10-7 说用 1.1.2.0 装载 Skills；但可读源码 `Demo-Skills-SpringAi 1.1.2/.../HelloSkills.java` 创建 `skillsHook` 后调用 `.hooks(List.of())`，**没有把它传进去**。按该文件原样，不能证明 Skills 已挂载。源码包未见 `src/test`；未执行 Maven 构建或整个旅游项目，因此只把它列作这个示例的确定性问题，不外推成全课代码都无效。

**优点。**Java 路线提供真实 POM 和不少源文件，工作流节点/边能供 Java 开发者阅读；Skills 章覆盖按需加载的思路。**不足与过时。**多个版本混杂，有 RC 依赖与后续发布的迁移风险；Python 主项目切到 Spring 只为展示多 Agent，没有时间收益。旅行规划多角色不等于售后审批状态机；抽查未见图像证据、商户隔离、补发幂等和独立评估。Skills 示例要先修 `.hooks(List.of(skillsHook))`（仍需确认该版本确切签名并实际运行），否则不能当可工作样例。

**选法。**当前最多读 7 章的图/状态概念、10-2～10-5 的 Skills 概念，暂不投入搭建。若岗位明确要求 Java/Spring，再花 8–12 小时选 4、6、7、10 章，选定同一稳定版本并做一个只读订单查询+审批状态的小 Java 对照；5、8、9 章后置。**当前投入/交付：**0–2 小时，一张 Java 方案备忘；不列为 12 周硬交付。**信心：中高**（目录、目标章转录和可读源码交叉验证；未构建运行，其他课件细节未逐项查）。

## 对现有 12–16 周路线的修订建议

现有[12 周路线](Agent应用开发学习路线与面试计划.md)已把单场景、评估前移、MCP 后置、人工审批、幂等和部署设为硬交付，主体**保留**。本审查修正的是“课程优先级”和三个容易被低估的工作量：

1. **第 1–4 周：课程输入只服务文本基线。**主学 LangChain 工具/结构化输出和 MCP 全栈 4/9 章选段；订单、政策和引用先用普通 Python/SQL 自己写。小哲是答疑词典，编程智能体作为第二例。第 1 周就给每条工单编号、政策版本和期望结果；第 4 周至少能区分“检索没找到”和“找到却答错”。
2. **第 5–8 周：把业务状态置于框架状态之前。**待审核、审批身份、重新查订单、唯一幂等键与超时结果查询应在数据库里可复测。LangChain 066 或 MCP 16-6 的人机交互只提供机制；只有恢复/分支复杂度真实升高才引入 LangGraph。第 7 周视觉结果按“可见事实、不确定、需补图”记录，沿用已有 C++ 图像处理优势，但必须用标注样本比较原图与处理图的收益。
3. **第 9–12 周：给评估和部署预留真实时间。**从第 2 周起持续跑固定样本；第 9 周做消融比较与失败分类，不要到末尾才凑指标。MCP 只做一个只读工具演示，不让它承担补发写入。第 11 周在干净环境完成依赖、数据库初始化、图片路径、密钥示例、重启恢复和最终留出集；第 12 周再写 README、视频和面试叙述。MCP 全栈 19-2 不能视为部署验收。
4. **时间守门。**12 周约 180–240 小时，课程与官方文档总量控制在约 36–48 小时；六门建议投入合计约 30–48 小时，按遇到的问题选，不用全额花完。若延期，先砍多 Agent、A2A、Milvus、Hermes 配置和页面装饰；不要砍工单状态、授权、审批、幂等、图像失败样本、评估和复现说明。

**选学停止条件：**某一节看完仍不能指出自己项目中的一个对应接口、状态或失败样本，就暂停该课，回到项目实现或官方文档。面试时只陈述自己真正运行、测量和修复的内容；模拟订单与补发必须明示为模拟。
